# GA4 이벤트 구현 요청 검토

사용자가 전달한 GA4 이벤트 구현 요청을 개발자 입장에서 검토하여, 구현 전에 반드시 확인해야 할 정보가 빠져 있는지 점검한다.

## 절차

1. 요청 내용을 읽고 이미 답변되어 있거나 명확한 항목은 제외한다.
2. 구현에 꼭 필요한데 빠져 있는 내용만 골라 질문을 만든다. 예를 들어 다음과 같은 관점을 점검하되, 이미 요청에 답이 있으면 질문하지 않는다.
   - 이벤트를 발생시키는 정확한 트리거 시점/조건
   - 함께 보낼 파라미터와 각 파라미터의 값 출처
   - 값의 타입/형식 (문자열, 숫자, 통화 단위 등)
   - 중복 발생(예: 새로고침, 중복 클릭) 방지 여부
   - 로그인/비로그인 등 사용자 상태에 따른 차이
   - 테스트/검증 방법 또는 완료 기준
3. 질문은 최대 3개까지만 고른다. 가장 구현에 영향이 큰 것부터 우선순위를 매긴다.
4. 질문이 하나도 없으면 "없음"이라고만 적는다.
5. 모르는 내용을 추측하거나 지어내지 않는다. 질문의 "이유" 칸에도 확인된 사실만 적는다.

## 출력 형식

검토 결과를 다음과 같은 마크다운 표로 작성한다.

```markdown
| 질문 | 답이 필요한 이유 |
| --- | --- |
| (질문 1) | (이유) |
| (질문 2) | (이유) |
| (질문 3) | (이유) |
```

질문이 없으면 표 대신 "없음"이라고만 적는다.

## 저장

작성한 검토 결과를 프로젝트 루트에 `developer-request-review.md` 파일로 저장한다. 이 스킬은 검토 문서만 작성하며, HTML/JS 등 실제 상점 코드는 절대 수정하지 않는다.
